# ainew — Integrations GUIDE

Module `integrations` attaches external sources. Domain menus fill **after** a successful connection.

| Menu | Path | Actions |
|------|------|---------|
| Inventory hub | `/integrations` | Source overview |
| UCMDB | `/integrations/ucmdb` | CMDB import |
| vCenter / OLVM | `/integrations/hypervisors` | VMware, oVirt, Proxmox, Hyper-V, OCP virt |
| Physical hosts | `/integrations/physical-hosts` | SSH/WinRM targets |
| Exadata | `/integrations/exadata` | Racks |
| OpenShift | `/integrations/openshift` | Cluster API |
| Backup (Veeam VBR) | `/integrations/backup` | Read-only Veeam REST connection (admin only): endpoint, user (recommended role Backup Viewer), REST API revision, CA/SSL. Without it the Backup & DR menu stays hidden. Revisions other than 1.3-rev1 are selectable with a "fields not verified" warning. A warning is shown when an external LLM is enabled because backup data (VM/job/repository names) reaches the model |
| Hardware management (Dell OME / HPE OneView–OVGD) | `/integrations/hardware` | Read-only REST (admin only); one “Add hardware management tool” button: **Dell OpenManage Enterprise (OME)**, **HPE OneView Global Dashboard (OVGD, appliances auto-discovered)** or **HPE OneView (single appliance)**; iLO/iDRAC are never contacted directly. Authentication is attempted ONCE; if rejected, sync halts (so the account is not locked) and only a successful “Test connection” resumes it. Data appears as a “Hardware” card + list badge in the Linux/Windows server drawer and ESXi host panel, in the **Events/Incident** flow (critical health, active critical alert → event → incident; recurring warnings → warning event), as «Related hardware» in the incident detail (blast radius: VMs, business services, cluster HA risk) and on the fleet page (`/hardware`, `hardware` module: fleet, enclosures, alerts, warranty/refresh report, suggestions + manual linking for unmatched). Menu, card, badge and the `/hardware` URL are hidden/redirected without a connection. |
| Automic (UC4) | `/integrations/automic` | Read-only Automic source DB (Oracle) wizard, test, discovery, collection — see Automation GUIDE (`modules/automation.md`); DBA grants: `automic-source-dba-grants.md` |

Add → test → save → sync. Writing integrations needs `integrations`; viewing virt dashboards needs `virtualization`. Automic system management needs `integrations`; viewing/assistant needs `automation`. Only admins manage the backup (Veeam) connection; Backup & DR pages need `virtualization`. The hardware-management connection is admin-only; two-level access: Linux/Windows/Virtualization users see the hardware **summary** of their own servers (health, model, enclosure/bay, warranty, alerts) in the card/badge/incident card; BMC IP, serial/service tag, UUID, firmware, console link and the fleet page need the separate `hardware` module (default admin only; manual linking `/hw/links` writes only inside ainew and needs at least the operator role; BMC data is never added to `/servers` APIs). **Host hardware logs (Phase 3a, OFF by default):** when Advanced Settings → “Host hardware logs” is enabled, ESXi hosts' IPMI SEL and vmkernel/vmkwarning hardware records are read through vCenter (the vCenter role needs `Global.Diagnostics`) and hardware records (MCE, EDAC/ECC, WHEA, PSU, thermal) from the existing Linux/Windows log collectors are parsed; iLO/iDRAC are not contacted, no new port/firewall/account is needed, nothing is written to the hardware. The result appears as a “Hardware logs” card in the Linux/Windows drawer and ESXi host panel only when records exist; records are kept 30 days and texts are masked. A hardware provider (OME/OneView) is not required.
